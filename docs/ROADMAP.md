# Auralis 迭代路线

更新日期：2026-10-25。

目标是让独唱练习从“能识别音高”走向“容易开始、反馈可信、失败可恢复、进步可回看”。优先完成能验证的练习流程；下列计划不代表功能已经上线，也不承诺固定发布日期。

## 已有基础

- 实时音高、标准音模唱、曲谱片段及循环练习，手机紧凑布局与曲线放大。
- 收音参数预设、面板内实时预览、环境与试唱两阶段自动校准。
- MusicXML / MXL / MIDI / JSON 导入、手动简谱、待校对的图片/PDF 简谱 OCR，以及可选 Audiveris 服务。
- TypeScript、前端测试、Python 服务测试和生产构建；GitHub Pages 验证流程及 Vercel Git 部署。

这些功能的已执行检查与实体设备验证边界记录在 [VERIFICATION.md](VERIFICATION.md)。布局模拟不等于设备实测，合成波形通过也不等于真人识别准确率已标定。

## 本轮交付：练习可回看，问题可定位

本轮开发范围如下。发布完成与否以验证记录和对应提交为准。

| 事项         | 验收标准                                                                                                                                         |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 完成练习记录 | 保留最近 100 次完整曲谱练习与近 7 天概览；显示速度、片段和反馈；无有效音高显示“—”，不把示范或中断计为完成；可导出/合并导入记录、载入原参数重练。 |
| 音频中断处理 | 系统停止收音或设备断开后停止使用旧数据；界面给出可操作提示，重新连接后能由用户主动重试。                                                         |
| 帮助与诊断   | 应用内能找到常见问题和反馈入口；诊断只在用户主动操作时复制，不自动发送。                                                                         |
| 开源支持     | 用户指南、贡献说明、缺陷与功能请求模板、发布验证记录完整可查。                                                                                   |

## 下一轮：设备可靠性与数据可携带

优先级高。先完成已知场景的实体设备实测，再决定是否调整算法与默认参数。

| 方向               | 验收条件                                                                                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 真实手机与平板测试 | 在至少一台 iOS/iPadOS 和一台 Android 设备记录系统/浏览器版本，验证授权、拒绝后重试、后台恢复、内置麦克风、耳机以及连续练习；明确失败场景。 |
| 收音与延迟基准     | 使用固定参考音和真人独唱，在安静/背景噪声环境记录检测稳定性与实际延迟；给出测量方法及适用范围，不以单个样本概括准确率。                    |
| 完整数据备份       | 提供带版本的曲谱、设置、历史备份及恢复预览；错误或不兼容文件不覆盖现有数据，跨域名迁移可验证。                                             |
| 存储与导入恢复     | 存储不可用、空间不足、文件损坏、OCR 中断等情况有明确反馈；用户保留重试或导出的路径。                                                       |

## 后续：练习组织与曲谱能力

优先级中。依据实际使用反馈选择，而非一次堆叠所有功能。

| 方向               | 验收条件                                                                                             |
| ------------------ | ---------------------------------------------------------------------------------------------------- |
| 曲谱库管理         | 搜索、重命名和删除自定义曲谱有明确边界；删除前可确认或撤销，不影响内置曲谱。                         |
| 更易理解的练习建议 | 依据覆盖率与音准分别给出下一步；对同曲、同片段、同速度的可比记录说明趋势，避免以总分掩盖漏唱。       |
| 选择旋律声部       | MusicXML / MIDI 导入时展示可选声部或轨道，选择后可试听核对；明确和弦、重叠音、反复与变速的处理方式。 |
| 可访问性检查       | 键盘可完成核心流程，焦点及弹窗关闭行为稳定；读屏能获取状态变化，动态读数不会连续打断操作。           |

## 单独设计后再实施

- **离线使用**：需确定资源缓存、版本更新提示和回退方案；离线前后不得混用不兼容资源，首次 OCR 资源下载应明确提示。
- **账号与云同步**：需先确定数据模型、导入冲突、删除/导出和运行成本。当前本地数据不会自动上传。
- **在线五线谱识别服务**：需明确文件处理、超时、资源限制、访问控制与第三方许可，再部署独立服务。现有静态站点不承担此能力。
- **录音回听与长期分析**：需先设计显式录音控制、存储上限和删除方式，不能悄悄改变“实时分析、不录音”的现有行为。

## 每轮发布的完成条件

1. 为本轮问题写出可复现的用户场景和预期行为，新增必要回归测试。
2. 前端测试、类型检查和生产构建通过；涉及识别服务时验证对应服务测试。
3. 在小屏与桌面验证核心操作、空状态、错误状态和恢复路径，记录未覆盖设备。
4. 同步源码、用户说明与验证记录；部署后确认公开入口加载本次构建，并复验本轮主要流程。
5. 将剩余问题写为可执行的下一项，不把待验证项标为完成。维护者确认发布目标与回退位置后执行上线。

当前 GitHub 工作流会运行前端、Python 服务测试和构建。本轮 Vercel 构建命令也先执行前端测试，再执行类型检查与打包；前端测试失败会使该次部署失败，不替换生产版本。它不等同于跨平台的 Deployment Checks，也不涵盖未运行的实体设备检查。
